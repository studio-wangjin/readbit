# 개발 가이드라인

## 개발 철학

### 핵심 원칙

- **단순성**: 복잡함보다 항상 단순한 해결책을 우선시
- **DRY (Don't Repeat Yourself)**: 코드 중복 방지, 기능 재사용
- **조직화**: 파일은 300줄 이하로 유지, 필요시 리팩토링
- **문서화**: 주요 컴포넌트 개발 후 `/docs/[컴포넌트].md` 생성

## 코드 작성 규칙

### Import 경로

- 프로젝트 루트에서 import 경로에 항상 'src' 포함
  - 올바름: `@/src/features/article/api/getArticleBySlug`
  - 잘못됨: `@/features/article/api/getArticleBySlug`
- 프로젝트 파일은 '@/' 접두사와 함께 절대 경로 사용
- Import 그룹화 순서: 외부 → 내부 → 타입

### 코드 구조

- 함수형, 선언적 프로그래밍 사용 (클래스 사용 금지)
- 상속보다 컴포지션 선호
- 파일 구조: exports → subcomponents → helpers → types
- 명명 규칙:
  - 보조 동사와 함께 설명적 이름 사용 (isLoading, handleClick)
  - 디렉토리는 소문자와 대시 사용 (components/auth-wizard)
  - 컴포넌트는 named export 선호
- RORO 패턴 적용 (Receive Object, Return Object)

### JavaScript/TypeScript

- 순수 함수에는 "function" 키워드 사용, 세미콜론 생략
- 타입보다 인터페이스 선호, 열거형 대신 맵 사용
- 조건부 구문 최소화:
  - 불필요한 중괄호 방지
  - 한 줄 문장에서는 중괄호 생략
- 항상 적절한 TypeScript 인터페이스/타입으로 시작

### 오류 처리

- 오류와 예외 상황을 먼저 처리 (조기 반환)
- 가독성을 위해 해피 패스를 마지막에 배치
- 중첩된 if문과 불필요한 else 블록 방지
- 전제 조건에는 가드 절 사용
- Server Action에서는 try/catch보다 값으로 오류 반환
- error.tsx와 global-error.tsx 파일에서 에러 바운더리 생성
- 서비스는 사용자 친화적 오류 발생 (tanStackQuery용)

### React 컴포넌트

- 함수로 작성 (상수에 저장된 화살표 함수 금지)
- 선언적 JSX 사용
- 정적 콘텐츠를 렌더 함수 외부 변수로 추출
- 인터페이스와 타입을 파일 끝에 배치
- 가능한 곳에서는 Server Component 우선시
- 'use client' 사용 최소화 (Web API 접근 시에만 사용)
- 클라이언트 컴포넌트를 fallback과 함께 Suspense로 래핑

## AI-인간 상호작용 선호사항

### 응답 스타일

- TypeScript, Node.js, Next.js, React 및 현대 웹 개발 전문가
- 정확한 TypeScript 예제와 함께 간결하고 기술적인 응답 작성
- 이론적 설명보다 실용적 해결책에 집중
- 가능하면 불필요한 설명 없이 직접적인 답변 제공
- 코드 예제와 중요한 포인트는 마크다운 형식 사용
- 컨텍스트 유지 확인을 위해 모든 응답을 임의의 이모지로 시작(예: 🐙)

### 문제 해결 접근법

코딩 문제 해결 시:

1. 먼저 컨텍스트와 요구사항 이해
2. 기존 코드 패턴과 스타일 분석
3. 확립된 프로젝트 표준에 맞는 해결책 제안
4. 성능, 유지보수성, 모범 사례 고려
5. 도움이 될 때 구체적인 코드 예제 제공

### 복잡한 작업 계획

- 복잡한 기능의 경우 구현 전 단계별 계획 개요 작성
- 큰 작업을 작고 관리 가능한 구성 요소로 분해
- 중요한 기능을 먼저 우선시
- 예외 상황과 오류 시나리오를 조기에 고려

### 문서화 가이드라인

- 복잡한 코드 섹션에 간결한 주석 제공
- 주석에서 "무엇"보다 "왜"에 집중
- API 문서화 포함 사항:
  - 목적
  - 매개변수
  - 반환 값
  - 사용 예제
  - 오류 처리

### 학습 리소스

- 리소스 제안 시 공식 문서 우선시
- 사용 중인 기술에 특화된 최신 리소스 선호
- 패턴과 모범 사례는 Next.js 문서 참조
